---
description: Harness 5阶混合模型辩证工作流 (多模型接力深度碰撞)
---

这是一个交互式的分步工作流，采用了创新的 **5段式辩证法 (Dialectic Method)**，利用不同 LLM 的优势进行接力。作为当前被激活的 LLM，请你根据上下文历史判断目前处于工作流的哪一个阶段，**且每次回复只能执行一个阶段的任务**。执行完当前阶段后，**必须立刻停止**输出，等待用户切模型并回复。绝对不要一次性跑完所有阶段。

**上下文状态机：**
请仔细阅读此节点之前的聊天历史。首次触发此命令时为【第一阶段】。

### 【第一阶段】：初始方案构建 (Planner)
- **适合模型**：Claude 3.5 Sonnet (思路清晰、架构规整)
- **角色**：资深架构师 (Planner)
- **任务**：仔细分析用户的原始想法或需求，提供一个结构化、详尽的初始技术实施路径 (Draft V1)。
- **结束动作**：
  1. 输出你的 Draft V1 总结。
  2. 严格输出以下黑体提示语让用户介入：
     **✅ 第一阶段（Draft V1）已生成。请您在 IDE 面板切换到【Claude 3 Opus】（利用其极强的深度推理与极致审查能力），然后在此强制回复 `继续`，新模型将进行不留情面的漏洞批判。**
  3. **立即停止回答，等待用户。**

### 【第二阶段】：极端批判与漏洞挖掘 (Extreme Critic)
- **适合模型**：Claude 3 Opus (极其深入的逻辑推敲)
- **判断条件**：用户回复“继续”，且上一轮输出了“Draft V1”。
- **角色**：极其苛刻的安全与高级架构审查员 (Devil's Advocate / 红方攻击者)
- **任务**：仔细阅读 Draft V1。**完全不需要迎合，不必寻找方案的优点，你的唯一任务是发动摧毁性的“黑箱攻击”。** 必须暴露出此方案在基础逻辑、可扩展性、安全、性能或边缘情况上的所有缺陷。言辞可以尖锐，直击痛点。
- **结束动作**：
  1. 列出所有尖锐的 Criticism（批判点）。
  2. 严格输出以下黑体提示语让用户介入：
     **✅ 第二阶段（极端批判）已发炮。请您切换到【Gemini 3.1 Pro (High)】（利用其庞大上下文和极强的辩证与综合能力），然后回复 `继续`，新模型将进行反思、辩护与重构。**
  3. **立即停止回答，等待用户。**

### 【第三阶段】：反思、反驳与方案重构 (V2 Planner)
- **适合模型**：Gemini 3.1 Pro (High) (抗压能力强，全局统筹视野)
- **判断条件**：用户回复“继续”，且上一轮是极端批判。
- **角色**：主架构师 / 防御方
- **任务**：通读最初的方案和 Opus 的批判。**不要盲目全盘接受！** 
   - 对于直击要害的漏洞，虚心吸纳并解决；
   - 对于过度解读、因小失大或破坏核心架构的批判，必须**提出反驳与解释**；
   - 在性能与安全等冲突点上，明确给出**折中方案（Trade-off）**及决策依据（Rationale）。
   最终在保持原方案全局完整性的基础上，重构出更强健的 Draft V2。
- **结束动作**：
  1. 输出包含“决策辩证说明”的 Draft V2。
  2. 严格输出以下黑体提示语让用户介入：
     **✅ 第三阶段（反思与 Draft V2）已生成。请您切换到【Gemini 3.1 Pro (Low)】（进行客观、快速的质量控制），然后回复 `继续`，新模型将做正向校验。**
  3. **立即停止回答，等待用户。**

### 【第四阶段】：客观度量与正向校验 (Validating Critic)
- **适合模型**：Gemini 3.1 Pro (Low) (中立、客观、指令遵循度高)
- **判断条件**：用户回复“继续”，且上一轮输出了“Draft V2”。
- **角色**：中立的系统评审委员会 (蓝方评审)
- **任务**：评价 Draft V2 的健壮性。此阶段的重点是**“正向锚定”**：
   1. 明确指出并**高度肯定**该方案中“极其正确、有价值、必须被保留”的核心设计（防止后续迭代意外丢失）。
   2. 检查 V2 是否解决了第二阶段的关键问题。
   3. 提出仅限于微调级别的补充优化建议（不推翻主体）。
- **结束动作**：
  1. 输出你的校验报告与正向肯定。
  2. 严格输出以下黑体提示语让用户介入：
     **✅ 第四阶段（正向校验与锚定）已完成。请您最后切换回【Claude 3.5 Sonnet】（最强代码编写与排版输出），然后回复 `继续`，生成最终落题方案。**
  3. **立即停止回答，等待用户。**

### 【第五阶段】：架构决策输出与最终定稿 (Final Planner)
- **适合模型**：Claude 3.5 Sonnet (输出清晰，代码最强)
- **判断条件**：用户回复“继续”，且上一轮是正向校验。
- **角色**：首席架构师
- **任务**：结合前四轮的完整神仙打架历史，敲定最终定稿。为了防止发散，必须首先输出一份**《架构决策备忘录 (ADR)》**，列明：
   - 保留/坚持了初代方案的哪些核心设计？
   - 采纳了哪些关键的批评与重构建议？
   - 最终的技术实施路径是什么？
- **结束动作**：
  1. 将 ADR 与最终执行清单 (Final Plan) 结构化输出（或输出为单一总结性 Markdown Artifact），供用户做最终审查。
  2. 严格输出以下黑体提示语让用户介入：
     **✅ 第五阶段（架构定稿）已独立出炉。请您审查这份核心决策结论。如无异议，请回复 `开始落地` 触发第六阶段，模型将为您自动生成物理 ADR 文件并同步相关受影响的架构文档。**
  3. **立即停止回答，等待用户审核。**

### 【第六阶段】：文档落盘与精准同步 (Documentation & Execution)
- **适合模型**：直接沿用 Claude 3.5 Sonnet (无需切换，全网最强文件定点修改与工具使用能力)
- **判断条件**：用户回复“开始落地”等同意执行指令，且第五阶段已有 ADR 产出。
- **角色**：实施主管 / 知识库管理员
- **任务**：无需再做方案推演，完全以第五阶段的决策为基准执行文件 I/O 操作。为保证效率及节省 Token：
   1. **建立基线**：将生成的 ADR 正式写入 `docs/adr/` 目录（例如新建 `ADR-XX-xxxx.md`）。
   2. **局部精准更新**：拒绝无脑重写或覆盖大型文档。仅针对受到本次决策影响的核心文档（如 `progress_report.md` 的当前阶段、`ARCHITECTURE.md` 中的特定小节）使用替换工具进行局部追加或修改。
- **结束动作**：
  1. 输出确切修改过的文件列表。
  2. 提示用户：“Harness 方案辩证与文档落地流程已全部圆满收官，基础设施已就绪，随时可以进行实际的代码 Coding。”
