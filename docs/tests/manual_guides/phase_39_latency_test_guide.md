# Phase 39 — 延迟优化与智能分层降级方案 人工测试操作手册

此手册用于详尽指导和验证 Phase 39 (Latency Optimization) 的全面覆盖测试。本次升级重点重构了闲聊响应管线、动态模型切流、异步知识库预加载以及基于信息熵的记忆过滤。需通过人工干预控制台与日志查看，确保系统延迟已显著降低且无功能退化。

## ⚠️ 测试前置准备

1. **备份并修改当前配置**：
   在 `config.json` 中配置一个专门的极速模型作为闲聊模型替代，例如基于 LiteLLM 或本地模型：
   ```json
   {
     "llm": {
       "fast_model": "volcengine/ep-xxxxx-fast", // 或者 "gemini-3.0-flash" 等低延迟高并发模型
       "model": "volcengine/ep-xxxxx-main"
     }
   }
   ```
2. **清除历史状态**：如果在前置测试中有未完成的对话（例如中断的 HITL 审批），请先手动清理并重启服务。
3. **开启日志级别**：为了观察 RAG 前置拉取和意图改写绕过情况，请确保 `logging` 级别至少为 `INFO` 或 `DEBUG`。
4. **启动服务**：
   ```bash
   python -m nanobot.server  # 或者您使用的具体启动命令
   ```

## 🟢 性能与路由机制穿透测试

### 1. L0 白名单极速响应测试 (Strict Whitelist Bypass)
**目标**：验证在极简“闲聊”意图下，系统能成功拦截并跳过漫长的语义改写网络请求。
**测试步骤**：
1. 向 Bot 发送精确匹配白名单的词汇，例如：“你好”、“在吗”、“hello”、“测试”、“早上好”。
2. 观察控制台日志输出。
3. 感知客户端收到首字回复的耗时。
**期望结果**：
- 控制台或日志应当打印/体现匹配到了 `intent = "chitchat_safe"` 事件。
- **关键点**：负责历史重现的 `rewrite_query_with_anchors` 不应被调用（网络开销环节中无该处耗时产生）。
- 整体首字响应时间相比重构前有明显缩减（理论下降 1-2 秒以上）。

### 2. 动态模型切流与工具保留测试 (Dynamic Routing & Tools)
**目标**：检验系统是否正确将闲聊引流至廉价且极速的模型通道，并且在此降级中没有强行剔除物理工具。
**测试步骤**：
1. 再次发送标准闲聊触发词：“测试”。
2. 检查 `ProviderFactory` 或底层 LLM 调用的 Payload 日志。
**期望结果**：
- 观察到 LLM API 请求实际发送至 `config.json` 中配置的 `fast_model`（由轮切策略接管当前单个 Turn 的执行）。
- Payload 中仍然包含完整的 `tools` 列表定义。模型并未由于进入快速模式而出现“致盲”断送外部交互能力的技术退步。

### 3. 解耦异步池化防死锁测试 (Decoupled Pre-Fetching)
**目标**：验证最为耗时的 `vector_memory.search` 与 `knowledge_graph.get_entity_context` 已经从同步阻塞主线程中剥离。
**测试步骤**：
1. 发送触发重逻辑的提问（非闲聊），例如：“结合目前的文档，帮我总结一下这个项目的洋葱架构。”
2. 监听后台模块运转时序。
**期望结果**：
- 能观察到 RAG 文档检索与 KG 实体查询是前置到 `build_messages` 被调用前独立起线程或事件循环并发执行的（借助 `run_in_executor` 或 `asyncio.to_thread`）。
- 同步方法 `build_messages` 不应该产生阻塞锁死，而是透明接收 `pre_fetched_rag` 和 `pre_fetched_kg` 对象并将内容拼接入提示词体系中。

### 4. 高熵记忆自适应提取测试 (Entropy-Based Knowledge Extraction)
**目标**：测试由于对日常对话放开防洪大坝（取消硬编码防写入），基于高约束提示词能否智能拦截废话并保存真正带高业务熵的数据。
**测试步骤**：
1. **测试用例A（短废话）**：发送：“早上好呀，今天天气不错。”
2. **测试用例B（高熵夹带）**：由于闲聊同样能路由到 `post_reflect`，随后发送：“哈喽，请记住我刚才升职了，并且我不再关注体育新闻方向了。”
**期望结果**：
- **测试用例A**：反思记忆模块分析结果应当为不满足写入门槛。日志表示由于缺少密度，不会发起落盘和写入向量动作。
- **测试用例B**：虽然开头是简单的哈喽并伴随轻度聊天，大模型依据提示词依旧能精准剥离出“升职”、“免去体育方向推送”等强设置参数并建立或覆盖长效记忆文件库中。

## 🔀 安全降级与边界自愈测试 (Edge-case Check)

### 1. fast_model 缺省容错测试
**目标**：验证在宿主提供极速模型失败或无配置时，是否依然能平滑运作。
**测试步骤**：
1. 在配置中彻底删除 `fast_model` 或设置为任意不可达状态。
2. 发送闲聊“在吗”。
**期望结果**：
- **不允许应用报错宕机或卡死**。
- 系统降级路由，继续选用主 `model` 完成回复。同时由于仍处于 `chitchat_safe` 分支下，依然能享受跳过 `rewrite_query_with_anchors` 的 L0 加速福利。

- [ ] 极速聊天通道未丢失 `tools` 体系挂载，避免了工具能力致盲。
- [ ] RAG 和 KG 前抽取已无损解耦并在并发线程正常完成传参透传。
- [ ] 日常常规回答无法污染记忆数据库 (被反射机制 LLM 限定成功主动过滤掉短文本)。
- [ ] “假闲聊/真设定”形式的话语，依旧能触发高熵特征入库逻辑。
- [ ] 撤去极速模型后也能通过主管道进行自适应兼容。
