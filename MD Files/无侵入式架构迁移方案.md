# 无侵入式架构迁移方案 (Phase 30+ ➡ Native Hooks)

问题的背景：我们在旧代码的 `nanobot/agent/loop.py` 中直接硬编码了大量高级优化功能（涵盖 Phase 31 - Phase 39），导致与上游官方代码演进发生剧烈冲突。

本次重构的**核心目标**：绝不修改官方的原生文件。我们将利用新版官方提供的 `AgentHook` 生命周期拦截器、以及 Python 的鸭子类型和 Monkey Patch，在官方代码**外部**包裹一层你的自定义逻辑。

## User Review Required

> [!IMPORTANT]
> **关于插件入口加载**
> 官方的架构通常会在启动时扫描 `nanobot/plugins/` 目录。我们所有的自定义文件都会放到这个目录下，利用 `setup(agent)` 进行挂载。由于我们完全剥离了原生的入侵影响，这可能需要通过 Python `@patch` 和钩子（Hooks）拦截大模型的返回，你需要确认是否接受这种全外挂式的解耦架构（这可能会稍微增加系统启动时的动态绑定时间，约 5ms，但换来的是**永久免疫合并冲突**）。

## Proposed Changes

---

### [Phase 39 延迟优化层] (Latency Optimization & Short-Circuit)

原先在 `loop.py` 中强插入的 L0 极速白名单与记忆提取修改将重构为一个生命周期 Hook。

#### [NEW] [plugins/ext_latency_optimizer.py](file:///D:/Python/HKUDS/nanobot/nanobot/plugins/ext_latency_optimizer.py)
实现 `LatencyOptimizationHook(AgentHook)`：
- **`before_iteration`**: 正则预判 `messages` 中的 chitchat。一旦命中 `r"^(你好|在吗|早上好)[！？\s~]*$"`，直接向 `AgentHookContext` 注入 `context.final_content = "你好！"`, `context.stop_reason = "chitchat_safe"`，阻断底层慢速 LLM。
- **动态降级路由**: 在 Hook 初始化时重写 (patch) 当前 `Provider`，对简单任务直接在内部替换为极速模型 (如 gemini-flash) 处理，完成后再释放回主模型。
- **基于熵的记忆拦截**: 使用装饰器包装原本的 `MemoryStore.consolidate`，拦截无用信息熵。

---

### [Phase 35/37 安全沙箱与 Trace 追踪] (Cross-Platform Sandbox & Post-Mortem)

原存在于 `verification.py` 和 `shell.py` 的平台硬编码黑名单将重构为一个拦截拦截器。

#### [NEW] [plugins/ext_security_sandbox.py](file:///D:/Python/HKUDS/nanobot/nanobot/plugins/ext_security_sandbox.py)
实现 `SecuritySandboxHook(AgentHook)`：
- **`before_execute_tools`**: 读取 `context.tool_calls`。
  - 对于 macOS 破坏性指令 (`osascript`, `launchctl`) 执行正则封锁。
  - 对于文件沙箱：在 Hook 层解析参数，若命中系统关键路径，直接修改该 Tool Call，或将 `context.error` 置为拦截警告，模拟一次失败的工具调用让大模型反思，而不是导致外层程序崩溃。
- **RPA 的动态风险提升 (Flaw 1 修复)**: 在载入此插件时，动态给 `RPAExecutorTool` 注入 `evaluate_risk` 方法，保证执行物理点击时必入 `DESTRUCTIVE` 评级，抛给 Smart HITL 处理。

#### [NEW] [plugins/ext_trace_archive.py](file:///D:/Python/HKUDS/nanobot/nanobot/plugins/ext_trace_archive.py)
实现 `ExecutionTraceHook(AgentHook)`：
- **`after_iteration`**: 如果存在 `context.error` 或检测到执行链失败，利用外部的 `_extract_trace_postmortem` 方法生成分析。
- 替代原有切断 JSON 结构的错误粗暴截断，通过流式拦截确保产生的 Trace 永远是合法的 JSON。

---

### [Phase 33 动作循环检测与 HITL 广播] (Fuzzy Loop Detection & Smart HITL)

#### [NEW] [plugins/ext_smart_hitl.py](file:///D:/Python/HKUDS/nanobot/nanobot/plugins/ext_smart_hitl.py)
这是最关键的交互逻辑外置：
- 注册针对 `bus.events` 的监听器或将逻辑融入 Hook。
- **Fuzzy Loop Detection**: 维护一张全局字典追踪 `session_id` 的调用踪迹。在 `before_execute_tools` 判断是否死循环，如果是，修改 `context.stop_reason` 并输出自修复提示词。
- **分布式原子并发锁 (Improvement 2 修复)**: 实现基于 `.lock` 文件的安全多端审批防止脏读。
